# 保险库易用性优化开发文档

日期：2026-09-09
状态：移动功能已实现。本文保留五项优化的目标、实现建议与验收标准；移动部分以当前实现为准。

## 1. 范围与现状

| 优化项 | 当前实现 | 目标 |
| --- | --- | --- |
| 删除按钮 | 详情使用普通 ghost 按钮，回收站使用“永久删除”文案 | “移入回收站”和彻底删除操作的按钮文字为红色 |
| 共享文案 | 新建条目的保存位置为“家庭共享” | 改为“共享” |
| 保存位置变更 | 更新接口支持通过新条目完成跨库移动，源条目及其历史在事务内删除 | 已录入条目可在个人保险库与共享库之间双向移动 |
| 身份地址复制 | 详情逐项显示，没有整组复制入口 | 一次复制姓名、拼接地址、联系电话 |
| 银行卡卡号 | 表单为 password 输入，详情使用遮蔽字段 | 新增、编辑、详情中直接显示完整卡号 |

适用于现有五类条目：登录凭据、SSH 密钥、银行卡、身份地址、安全笔记。移动功能沿用现有权限：个人条目仅本人管理，共享条目仅创建者管理；管理员不获得额外条目权限。

以下属于本文约定：彻底删除入口统一称为“彻底删除”；地址包含邮编、非空部分以一个空格连接；移动按当前条目创建目标条目，不复制历史版本并删除源条目。开发时以这些约定为默认，不扩展为成员间转让或批量移动。

## 2. 删除按钮使用红色文字

### 行为要求

- 覆盖详情弹窗、独立详情操作区、回收站列表以及删除确认弹窗中的执行按钮。
- “移入回收站”“彻底删除”及其“移入中…”“删除中…”状态使用现有 `accent` 红色（`#CC0000`）。
- 默认、悬停、键盘聚焦状态保持红色文字；禁用态允许降低透明度。使用浅色背景保证可读性，避免红底红字。
- 取消、恢复、关闭等按钮保持各自语义，删除确认流程和权限不变。
- 当前“永久删除”按钮、确认标题统一改为“彻底删除”；说明文字仍可使用“永久清除”。

### 实现建议

在 `web/src/design-system/Button.tsx` 增加语义明确的危险操作变体，并在删除入口与确认组件中复用。不要依赖追加 `text-accent` 覆盖原有 `text-ink`，以免同优先级样式和 hover 样式冲突。通用确认组件的其他使用场景需要回归。

### 验收

详情删除、回收站彻底删除和两类确认按钮的可见文字均为红色；悬停不变为黑色或白色。键盘聚焦清晰，提交期间不能重复点击，取消不会触发删除。

## 3. “家庭共享”改为“共享”

将 `ItemEditor.tsx` 保存位置选项改为“共享”，并检查其他面向用户的同义入口、提示及测试断言。现有“共享库”等上下文名称可保留。

只调整展示文案，API 枚举 `personal` / `shared`、数据库字段和权限模型不改名；历史设计文档可以保留原始措辞。

验收：新建与编辑保存位置均显示“个人保险库 / 共享”，当前产品界面不再出现“家庭共享”。

## 4. 已录入条目双向变更保存位置

### 4.1 用户交互

在编辑表单中开放“保存位置”选项；条目类型仍不可修改。更改选项只修改草稿，保存成功后才生效。位置属于 dirty 状态，取消、关闭、离开页面沿用未保存变更保护。

保存时若位置发生变化，显示二次确认：

- 个人 → 共享：“移动后将创建一个新的共享条目并删除当前条目，历史记录不会保留。仍要继续吗？”
- 共享 → 个人：“移动后将创建一个新的个人条目并删除当前条目，历史记录不会保留。仍要继续吗？”

取消确认保留草稿且不发起请求。确认后保存成功刷新详情、列表、搜索及相关缓存，使用服务端返回的新条目 ID，提示“已移至共享”或“已移至个人保险库”。当前筛选不包含目标库时，源条目从该列表消失，详情切换到新条目并标注新位置。列表刷新失败不能误报移动失败。

### 4.2 权限与数据映射

| 来源 | 可执行人 | 目标字段 |
| --- | --- | --- |
| 个人 → 共享 | 当前个人条目所有者 | `vault_scope=shared`，清空 owner，creator 为当前用户 |
| 共享 → 个人 | 当前共享条目创建者 | `vault_scope=personal`，owner 为当前用户，清空 creator |

字段清空方式遵循现有数据库约束。前端沿用 `canManage` 控制编辑入口，服务端独立检查原条目的写权限。归属身份由服务端生成，禁止客户端指定其他所有者或创建者。

移动保留类型、提交的当前内容、标签、收藏和 payload 中现有的关联 ID，但生成新的条目 ID；目标条目的创建时间、更新时间使用移动时刻，revision 固定为 1。源条目及其历史版本在同一事务中删除。回收站条目须先恢复再移动。

### 4.3 更新接口

现有 `PUT /api/v1/items/{itemId}` 增加了可选的 `vault_scope`，兼容旧客户端省略该字段时保持原位置。例如：

```json
{
  "revision": 8,
  "vault_scope": "shared",
  "payload": { "name": "示例笔记", "body": "示例内容" },
  "tags": [],
  "favorite": false
}
```

沿用现有会话、CSRF、校验和 revision 冲突机制，成功返回更新后的完整详情。非法 scope 返回参数错误；权限不足与不可见条目沿用现有错误约定。冲突保留草稿并要求重新读取，不能自动覆盖。相同 scope 走普通更新，不重复触发移动逻辑。

更新 `internal/httpapi/items.go` 的请求结构、vault 更新输入及 OpenAPI 契约。scope 变更进入专门的移动流程，继续禁止客户端任意指定 owner/creator。移动请求使用可选的 `Idempotency-Key`；相同 scope 仍走普通更新，不重复触发移动逻辑。

### 4.4 加密与历史版本

现有 AAD 绑定条目 ID、scope、owner/creator、payload 版本及 revision；因此移动不直接修改源条目的 scope 数据列，也不尝试在目标库复用历史版本。

移动在一个数据库事务中完成：

1. 读取源条目，检查写权限、删除状态和请求 revision。
2. 使用原归属 AAD 解密当前内容，仅用于补齐省略的标签和收藏；目标内容以本次提交的当前 payload 为准。
3. 生成目标归属和新的 UUID，以目标 AAD、新 nonce 和 revision 1 加密并插入目标条目。
4. 写入目标创建审计和移动审计，按 revision 条件删除源条目；源条目的 `item_versions` 随外键级联删除。
5. 所有操作成功后提交事务。

任一步失败整体回滚，不得留下目标副本或删除源条目的半完成状态。移动后旧源 ID 不再可读，目标从 revision 1 开始且没有历史版本。移动后的后续编辑按普通更新规则产生历史版本。

移动审计沿用现有事件机制，记录操作者、源条目 ID、目标条目 ID、来源和目标 scope，不记录明文内容。目标归属由服务端从操作者和目标 scope 派生。

### 4.5 身份地址引用

现有银行卡 `billing_address_item_id` 和身份地址引用逻辑保持不变。移动不新增正向或反向引用处理；当前 payload 中已有的关联 ID 随当前条目原样复制。

`IdentityPayload`、`billing_address_item_id` 以及现有引用校验、恢复和可见性规则继续有效。本次移动不会扫描、改写、清空或自动移动关联条目；不因移动新增引用约束。

### 4.6 可见性与失败状态

共享移至个人后，其他成员后续详情、历史、搜索、导出及写入请求必须按新权限检查。已有页面在下一次刷新或请求发现权限失效时清除该详情；本功能不承诺撤回其他成员已经读取或复制的数据，也不新增实时推送机制。

网络失败保留草稿。移动请求使用稳定的 `Idempotency-Key`，响应丢失后以相同请求重试可返回同一个目标条目，避免重复移动；幂等键复用不同内容时返回冲突。锁定、退出和会话失效沿用当前数据清理流程。

## 5. 身份地址一键复制

### 格式与字段规则

身份地址详情增加“复制身份地址”按钮，有读取权限的用户均可使用。一次写入剪贴板的文本固定为三行，使用全角冒号、LF 换行，不增加尾部空行：

```text
姓名：张三
地址：广东省 深圳市 南山区 科技园科苑路 1 号 518000
联系电话：13800138000
```

- 姓名取 `full_name`，不使用条目名称 `name` 代替。
- 地址按 `state → city → district → address_line → postal_code` 顺序拼接，排除 `country`。
- 每部分去掉首尾空白，内部换行转为空格，忽略空部分，非空部分用一个空格连接。保留正常内部空格，避免破坏英文地址。
- 联系电话取 `phone`，保留 `+`、前导零及分机信息；姓名、电话也需去掉首尾空白并将换行转为空格，以保持三行格式。
- 公司、邮箱、备注不属于复制内容。字段缺失时保留对应标签，值为空；全空时仍遵循相同格式。

### 实现与反馈

提取纯格式化函数供组件和测试复用。复制必须由用户点击触发，剪贴板写入成功后显示“已复制身份地址”，失败显示“复制失败，请重试或手动复制”，不能误报成功。保持复制按钮可访问名称和状态反馈。

复用项目适用的剪贴板生命周期处理；自动清理为尽力行为，不保证浏览器一定允许。不得把地址写入日志、持久缓存或审计内容，也不要复用密码字段的审计枚举伪造地址事件。

## 6. 银行卡卡号明文输入与显示

`CreditCardFields.tsx` 的卡号输入改为 `type="text"`，可搭配 `inputMode="numeric"` 和现有 `autoComplete="off"`。卡号始终按字符串处理，不用 number 输入或数值转换，避免前导零丢失和长整数精度问题。删除“保存后以遮蔽形式显示”的提示。新增和编辑复用同一规则。

详情中的卡号默认显示完整值，不需要点击眼睛图标，重新打开仍直接显示；保留卡号复制能力和现有复制审计。优先使用专门的明文卡号展示组件，或为现有组件增加明确的显示模式，不要全局改变敏感字段默认行为。

CVV、PIN、登录密码和私钥继续按现有规则遮蔽。`number` 的敏感分类及存储加密保留；展示方式改变不等于取消复制审计。直接显示无需伪造一次“点击显示”事件，现有详情读取审计继续生效。该规则也覆盖未来复用详情组件的历史内容展示。

验收：新建、编辑、查看均显示完整卡号；前导零和长卡号往返保存不变；复制结果与存储字符串一致，其他敏感字段显示和审计不受影响。

## 7. 开发拆分与验证

| 工作包 | 主要位置 | 必须验证 |
| --- | --- | --- |
| 删除样式与共享文案 | `Button.tsx`、确认组件、`ItemDialog.tsx`、`ItemDetail.tsx`、`TrashPage.tsx`、`ItemEditor.tsx` | 默认与 hover 的实际文字颜色、确认与禁用状态、文案 |
| 地址整组复制 | `ItemDetail.tsx`、格式化工具、剪贴板工具 | 三行精确文本、排除国家、空值、邮编、英文空格、换行、复制拒绝 |
| 卡号显示 | `forms/CreditCardFields.tsx`、`ItemDetail.tsx`、`SensitiveField.tsx` | 字符串无损、完整显示、复制审计、CVV/PIN 遮蔽 |
| 后端移动 | `internal/httpapi/items.go`、`internal/vault/{policy,service,repository}.go`、审计与 API 契约 | 权限、原子性、AAD、新 ID、revision 1、源历史删除、幂等和冲突 |
| 前端移动 | `ItemEditor.tsx`、`VaultPage.tsx` | 编辑位置选项、确认、dirty 保护、筛选刷新、失败保留草稿 |

建议先实现低耦合的文案、颜色、复制和卡号展示，再完成后端移动及前端接入。双向移动上线前必须覆盖：

1. 五类条目分别完成个人 → 共享 → 个人，内容、标签和收藏保留；每次移动生成新 ID，目标 revision 为 1。
2. 有历史版本的源条目移动后源条目及历史删除，目标不复制历史；目标后续普通编辑仍按现有上限保留历史。
3. 其他成员及非创建者管理员不能移动；共享转个人后旧读者不能继续通过 API 访问。
4. 编辑与移动并发只接受符合 revision 的提交；加密、历史写入或审计失败时全部回滚。
5. `IdentityPayload` 和 `billing_address_item_id` 在移动中原样保留，现有引用和历史、回收站恢复规则不被改变。
6. 手机与桌面可完成复制、保存位置变更、删除确认，长卡号不导致布局溢出。

实现阶段运行相关 Go 测试、`npm --prefix web run typecheck`、`npm --prefix web test -- --run`，并按 `scripts/test-browser-e2e.sh` 的现有流程运行浏览器回归。颜色需检查实际渲染样式，不能只断言 class 字符串。

移动实现已落地；上述移动验收由后端集成测试、前端测试、类型检查和构建覆盖。其余优化项继续沿用各自已有实现与验收记录。
