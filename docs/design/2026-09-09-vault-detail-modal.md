# 保险库详情弹窗：设计与实现

日期：2026-09-09  
状态：视觉方案已确认，待实现。本文档不代表业务代码已完成。

## 1. 目标与设计依据

将保险库桌面端右侧详情、移动端列表下方详情，统一改为自适应模态弹窗。列表保留搜索、筛选和滚动位置，用户关闭弹窗后继续浏览。

用户已确认以下预览的视觉方向：

- [交互设计稿](http://158.178.243.20:28888/)
- [桌面设计图](http://158.178.243.20:28888/desktop.png)
- [移动端设计图](http://158.178.243.20:28888/mobile.png)

预览是临时服务，使用虚构数据；本文中的规格是持久实现依据。预览里的复制反馈、保存、收藏筛选和原生确认框只是演示，正式实现必须接入现有真实业务流程。预览中的导航、品牌标语和演示标签不作为页面改版要求。

视觉遵循 [style.md](../../style.md)，沿用 React 19、Tailwind CSS 4、现有设计 token、Button、Status 和自托管字体。无需增加 UI 库或修改后端接口、数据库结构。

## 2. 范围

本次实现包含：

- 列表占据原主内容容器，移除右侧占位详情和移动端重复详情。
- 详情、新建、编辑、历史在同一个弹窗容器内切换。
- 保留登录信息、SSH 密钥、银行卡、身份信息、安全笔记全部字段和操作权限。
- 兼容详情直达地址、浏览器前进后退、密码生成器传入的新建草稿。
- 删除、历史恢复、放弃编辑使用统一确认弹窗。
- 补齐弹窗焦点、背景滚动、异步请求与敏感字段生命周期处理。

回收站仍为独立页面；不重做全站导航，不新增密码业务能力，不把设计稿中的静态示意数据带入产品。

## 3. 布局规格

### 页面与列表

页面继续使用居中的 `max-w-screen-xl` 容器。搜索、类型筛选、收藏、健康提示、新建和回收站入口保留。列表扩展到完整内容宽度，采用紧凑报纸式行布局。

桌面行按「条目标题及辅助信息 / 类型 / 所属保险库 / 打开标识」分栏，使用实线建立层次；移动端合并次要信息到标题下方。共享条目的创建者信息不可因响应式折叠而丢失。单条记录使用可聚焦按钮，不放嵌套交互控件。仅显示现有元数据，不为了填充分栏新增详情请求。

搜索输入增加 `min-width: 0`，窄屏工具栏可换行。列表空态、搜索无结果、分页和错误反馈保持可用。

### 弹窗尺寸与分区

| 项目 | 桌面和平板（≥768px） | 移动端（<768px） |
| --- | --- | --- |
| 宽度 | 最大 768px，左右至少 24px | 视口宽减 16px |
| 高度 | 最大 `calc(100dvh - 48px)` | 最大 `calc(100dvh - 16px)`，同时处理安全区域 |
| 正文内边距 | 24px | 16px |
| 标题 | 36px，`font-display` | 30px，`font-display` |
| 操作区 | 横排，危险操作靠右 | 两列排列，必要时单列 |

容器使用纵向 flex：标题区和操作区不收缩，正文 `min-height: 0; overflow-y: auto`。只让正文滚动，关闭按钮和主要操作始终可达；横向禁止溢出。软键盘出现时以动态视口高度约束正文。

标题区依次显示类型标签、条目标题、保险库归属、版本和更新时间，右上角为关闭按钮。长标题允许换行，不能覆盖关闭按钮。弹窗只保留一个主标题，绑定可访问名称。

详情正文使用小号字段标签、清晰的数据文本和细分隔线。登录详情以用户名、密码、网址为主，桌面标签与备注可分为两栏，移动端折叠为单栏。其余类型按现有字段结构排布，不强行套用登录详情分组。私钥、安全笔记保留换行并允许长串折行。

### Newsprint 视觉约束

- 背景 `paper (#F9F9F7)`，正文与边框 `ink (#111111)`，次要分隔 `divider (#E5E5E0)`。
- 弹窗外框 2px 实线，内部主要分区 1px；相邻边框避免叠加。
- 所有圆角为 0，不使用背景模糊、渐变遮罩或柔和阴影。
- 遮罩使用 `bg-ink/40`；红色 `accent (#CC0000)` 仅少量用于标记、链接装饰和危险操作。
- 标题 `font-display`，普通文字 `font-body`，数据与元信息 `font-mono`，UI 使用现有字体约定。
- 间距优先使用现有 8px 网格；按钮与关闭入口至少 44×44px。
- 保留全局纸张纹理，不额外叠加妨碍密码阅读的纹理。
- 可使用 150–200ms opacity 过渡，不使用弹跳；遵循 `prefers-reduced-motion`。

## 4. 状态与交互

使用明确的弹窗模式，替代 `creating`、`editing`、`historyFor` 等容易形成冲突组合的独立开关。建议模式为 `closed / loading / detail / create / edit / history / error`，并单独管理当前条目 ID、数据、请求标识和顶层确认状态。

| 事件 | 结果 |
| --- | --- |
| 点击条目 | 立即进入 loading 并打开弹窗；获取详情成功进入 detail |
| 获取失败 | 弹窗内展示错误、request ID、重试及关闭入口，不留下旧条目内容 |
| 关闭详情或历史 | 关闭整个弹窗，恢复列表位置与触发按钮焦点 |
| 点击编辑 | 同一弹窗进入 edit，载入当前数据 |
| 取消编辑 | 无修改直接回详情；有修改确认放弃后回详情 |
| 编辑保存成功 | 返回更新后的 detail，刷新列表；保留当前搜索和筛选 |
| 点击新建 | 进入 create；支持生成器的一次性内存草稿 |
| 新建保存成功 | 展示新条目的 detail，更新列表与详情地址 |
| 点击历史 | 同一弹窗进入 history；“返回详情”恢复 detail |
| 历史恢复成功 | 展示新 revision 的 detail，刷新列表 |
| 移入回收站 | 打开确认层；成功关闭整个详情，更新列表；失败保留上下文并显示错误 |
| 收藏切换 | 真实请求成功后更新详情和列表；按现有权限显示操作 |

只读共享条目保留现有权限边界，不因设计稿出现按钮而扩大修改权限。历史恢复等写操作仍由服务端验证权限。

只读模式支持关闭按钮、Esc 和点击遮罩关闭；仅点击面板外部触发关闭，正文拖选不误触。编辑或新建有未保存变更时，所有关闭入口走同一个放弃确认流程；浏览器后退也不能静默丢弃草稿。刷新或关闭标签页可用 `beforeunload` 的浏览器原生提示，不能依赖它提供自定义文案或绝对保护。

保存、删除和恢复期间防止重复提交；确认按钮显示忙碌状态。写操作提交后不将“关闭 UI”视为服务端撤销，完成与失败结果必须有明确处理。

列表刷新失败与保存失败分开反馈：条目已保存时保留最新详情，提示列表刷新失败并允许重试，避免用户重复提交。

## 5. 路由和浏览器历史

所有设备统一支持 `/vault/:itemId`，路径代表列表之上的详情弹窗，不再根据 1024px 媒体查询决定是否导航。

- 从 `/vault` 点击条目：push 详情路径，由路由驱动打开与加载；保留已挂载列表，避免双重 fetch。
- 从列表打开后关闭：回退到本次弹窗对应的列表历史项，不再额外 push `/vault`。
- 直接访问或刷新详情 URL：加载列表和指定详情；关闭用 replace 回 `/vault`，不能无条件 back 到站外。
- 浏览器后退关闭弹窗，前进重新打开；路由去掉 itemId 后必须关闭，不能由 selected 状态重新打开。
- 编辑和历史作为弹窗内部模式，不追加独立 URL 历史项。
- 新建阶段保持 `/vault`；保存成功后建立新条目的详情导航项。
- 删除后将当前详情历史项替换为 `/vault`；以后访问过期地址时正常展示不存在或无权访问，不自动循环重试。

`router.tsx` 当前仅有 push 导航，需要增加最小的 replace 和可识别本应用导航来源的支持。历史元数据只存导航标记，不存标题、搜索词、密码、条目 payload 或生成器草稿。来源标记需区分当前页面生命周期，刷新详情按直接访问处理。

路由监听负责同步状态，关闭处理负责选择 back/replace，避免二者互相触发。未保存编辑的 popstate 需要先暂缓路由离开并展示确认：取消恢复当前详情路径，确认完成原离开意图。为此增加最小导航拦截能力，测试重复后退、取消和确认后历史栈不增长；不通过反复 push 路径来模拟阻止返回。

## 6. 组件调整

| 文件 | 改动 |
| --- | --- |
| `web/src/design-system/Dialog.tsx` | 提供通用 Dialog，ConfirmDialog 复用，保留原有调用接口 |
| `web/src/features/vault/ItemDialog.tsx`（新增） | 组合标题、滚动正文、底部操作和不同模式；避免在页面内重复 JSX |
| `web/src/features/vault/VaultPage.tsx` | 移除两套详情节点及宽屏判断，管理路由、模式、加载、刷新和触发元素 |
| `web/src/features/vault/ItemDetail.tsx` | 复用全部字段渲染，拆分标题与操作插槽，消除双重标题和内边距 |
| `web/src/features/vault/ItemEditor.tsx` | 暴露 dirty、提交状态和操作区组合能力，保留验证与冲突处理 |
| `web/src/features/vault/HistoryPage.tsx` | 适配弹窗正文和返回入口，保留分页与恢复确认 |
| `web/src/features/vault/SensitiveField.tsx` | 验证卸载重置，并调整复制清理的生命周期 |
| `web/src/app/router.tsx` | 最小扩展 replace、来源标识及未保存编辑导航处理 |
| 前端组件测试与 `tests/e2e/vault.spec.ts` | 用弹窗行为替换侧栏和 `mobile-detail` 断言 |

通用 Dialog 优先使用原生 `<dialog>` 和 `showModal()`，由浏览器提供 top layer、背景 inert 和基础焦点约束。组件统一处理 React open 状态、cancel、遮罩点击、初始焦点、恢复焦点及 body 滚动锁定。不要同时保留两套互相竞争的手写焦点陷阱。

标题和描述 ID 使用 `useId()`，避免现有固定 `dialog-title` 在多层弹窗中重复。关闭后恢复至仍存在的触发按钮；条目已删除时回到列表的稳定入口。加载态可先聚焦关闭按钮或标题，不自动聚焦敏感值。

确认层同样使用通用 Dialog。顶层确认打开时下层不接收 Esc、Tab 或遮罩点击，取消后焦点回到下层操作按钮。滚动锁按打开数量统一管理，关闭确认层不能提前解锁页面；旧 ConfirmDialog 的其他使用方也要回归。

## 7. 异步、敏感数据与错误

每次详情请求使用独立 AbortController，沿用现有 `request` 的 `signal` 支持，并使用请求序号或当前 ID 校验作为防线。关闭、切换条目、离开页面时终止读取；迟到响应、异常和 finally 都不能覆盖新条目或重新打开弹窗。Abort 不展示普通业务错误。

关闭后卸载字段并清空详情与草稿引用，重新打开重新获取且默认遮蔽。卸载不代表能够从 JavaScript 堆中保证擦除字符串；不作此类承诺。锁定、退出、会话失效仍沿用现有全局清理和请求中止流程。

密码显示和复制继续保留审计与现有自动遮蔽行为；按条目 ID 隔离字段状态，避免两个相同密码条目之间继承 revealed 状态。

当前 SensitiveField 会在卸载时取消剪贴板定时器。弹窗关闭更频繁，因此把尽力清理剪贴板的任务移到会话级管理：关闭详情不取消已安排清理，30 秒后仅在剪贴板仍匹配本次复制值时尝试清除；新的复制替换旧任务。完成或失败后释放值引用，锁定与退出时释放会话内引用。浏览器拒绝访问或页面结束时无法保证自动清理，保留准确反馈，不通过日志或持久存储保存密码。

列表错误位于列表；加载、保存、收藏、恢复和删除错误位于当前可见弹窗或确认层。401 交给统一会话处理；404/无权限展示可关闭错误态；revision 冲突保留现有处理，不覆盖用户输入。

## 8. 实现顺序

1. 提取通用 Dialog，适配 ConfirmDialog，完成基础焦点、层叠、滚动行为。
2. 增加 ItemDialog，重构详情分区，完成桌面和移动端静态布局。
3. 合并 VaultPage 状态与详情渲染，接入读取、路由、关闭和请求取消。
4. 接入新建、编辑、生成器草稿、历史、收藏与删除，以及未保存修改保护。
5. 修正敏感字段卸载与剪贴板清理生命周期，完善失败状态。
6. 更新行为测试，运行前端类型检查、组件测试和现有浏览器测试流程，按设计图人工核对。

## 9. 验收标准

- 在 390px、768px、1440px 宽度验证：详情只渲染一份、背景不可操作、页面无横向溢出。
- 超长标题、SSH 私钥、多行安全笔记及大量历史记录可阅读；关闭和操作区始终可达。
- 点击后立即出现加载态；失败可重试，关闭后迟到响应不产生详情或错误残留。
- 关闭返回原搜索、筛选、分页和滚动位置；未被删除的触发条目恢复焦点。
- 直达、刷新、后退、前进和删除后的路由行为符合第 5 节；请求不重复循环。
- 编辑 dirty 保护覆盖取消、关闭、Esc、遮罩、站内导航和浏览器后退。
- 新建及生成器草稿、编辑保存、版本冲突、历史恢复、收藏、删除成功和失败均正常。
- 各类条目及只读共享权限回归通过；正文只有一个可访问弹窗标题。
- Tab/Shift+Tab 留在顶层弹窗，Esc 仅关闭最上层，确认关闭后页面仍锁定。
- 重新打开或切换条目后敏感值默认隐藏；复制审计、自动遮蔽及关闭后的尽力剪贴板清理符合约定。
- 会话锁定或失效后所有弹窗与敏感数据引用清理，迟到请求不恢复界面。
- 使用现有测试环境运行 `npm --prefix web run typecheck`、`npm --prefix web test -- --run`；浏览器测试通过 `scripts/test-browser-e2e.sh` 现有临时服务器流程执行。
