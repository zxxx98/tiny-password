# T06 · 登录、会话与密码生命周期

依据：总行动计划 T06（用户已授权实现）与设计 §10.2。M1 修复基线为 `4d319cd`。

- [x] 以真实 SQLite 和可注入时钟建立认证 API、会话边界、限流及并发回归测试，确认失败。
- [x] 实现 auth 服务：Argon2id 验证；未知账号执行等价 dummy 验证；32-byte 随机会话仅持久化 SHA-256，另用公开随机 ID 管理会话。
- [x] 增量迁移保存用户 5–30 分钟闲置偏好（默认 15）；24 小时绝对期限。GET 查询不续期，显式用户活动 POST 才续期，不能恢复过期/撤销会话。
- [x] 登录限流采用 SQLite 事务预留计数，用户名/来源/全局默认每分钟 5/20/100 次；成功和失败都计数，不信任转发头。改密也限流。
- [x] 登录插入会话重新比较密码哈希与账号状态；改密事务比较旧哈希及会话有效性、撤销所有旧会话并发放新会话，避免并发请求恢复旧权限。
- [x] 接入登录/退出/当前会话/本人会话列表与撤销/改密/活动/闲置偏好 API；首次改密期间只允许当前会话信息、改密和退出。
- [x] 登录使用预认证 CSRF；成功消费旧上下文，认证写请求使用绑定新会话的 CSRF token。Cookie 默认 Secure/HttpOnly/SameSite=Lax；仅明确开发开关可放宽。
- [x] 更新 OpenAPI 与验证记录，完成 Go/race/vet、容器 API 冒烟及独立代码复查。登录和账户 UI 属后续 T15。

补足合同：GET `/auth/session` 提供当前用户、期限与会话绑定 CSRF；POST `/auth/session/activity` 仅由真实交互触发；PATCH `/auth/preferences` 修改闲置分钟数。改密返回 204，轮换 Cookie 并在 `X-CSRF-Token` 响应头提供新 CSRF。会话列表返回全部有效本人会话，`next_cursor: null`，后续若增加分页需完善合同。
