# R2 环境变量凭证支持设计

## 目标

允许内网部署直接通过环境变量提供 R2 的 Access Key ID 和 Secret Access Key，同时保留当前 Docker Secret 文件方式，避免破坏已有部署。

## 方案

新增两个运行时环境变量：

- `TP_R2_ACCESS_KEY`
- `TP_R2_SECRET_KEY`

R2 resolver 每次执行时按以下顺序取值：

1. 对应环境变量非空时使用环境变量值。
2. 环境变量为空时读取现有凭证文件路径：`TP_R2_ACCESS_KEY_FILE` 与 `TP_R2_SECRET_KEY_FILE`，默认分别为 `/run/secrets/r2_access_key` 和 `/run/secrets/r2_secret_key`。
3. 两种来源都缺失时，R2 目标保持未配置；文件存在但不可读时继续 fail closed。

Endpoint、桶名和对象前缀仍只从管理员系统设置读取；凭证不进入 SQLite、管理 API 响应、备份归档、审计记录或普通日志。管理页面继续只显示“已注入/未挂载”的布尔状态。

## 数据流与兼容性

应用启动时不把凭证写入数据库。R2 resolver 在每次手动备份、定时备份和 incoming 清扫前解析设置与凭证，使环境变量和文件方式具有相同的运行时生效边界。

现有 `deploy/compose.r2.yaml` 文件挂载方式继续可用。环境变量部署者可在 Compose 的 `environment` 中提供两个新变量，并仍需配置 Endpoint、桶名和前缀。文档将明确指出：环境变量值可能被容器检查、进程环境或部署日志暴露，仅适合用户明确接受该风险的受控内网环境。

## 错误处理

- 只设置其中一个凭证且另一个凭证的文件来源也缺失时，R2 目标不可用，不允许以部分凭证运行。
- 环境变量为空字符串时视为未设置，并回退到凭证文件。
- 非空环境变量优先于凭证文件；这使临时测试可以覆盖已挂载的旧凭证。
- 凭证值不写入错误消息或诊断输出。

## 测试与验收

增加 resolver 测试覆盖：

1. 两个环境变量都设置时成功构造 R2 client。
2. 环境变量缺失时回退到凭证文件。
3. 环境变量覆盖凭证文件。
4. 只设置一个环境变量且没有对应的文件回退时不构造交付目标。
5. 未配置任何来源时保持未配置。

现有 R2 假服务、备份 API、凭证文件检查和全量测试必须继续通过；同时更新部署文档与 Compose 配置示例。
