## 1. 文档目的

本文档定义 Tiny Password V1 的产品范围、权限模型、系统架构、安全边界、数据模型、用户界面、备份恢复、部署方式、测试策略和验收标准。它是后续任务拆分、实现和评审的共同依据。

Tiny Password 是一款面向家庭、小型可信群体的自托管密码管理器。产品强调功能精简、数据可控、部署轻量、恢复可靠，不追求企业密码管理平台的组织结构、审批流和横向扩展能力。

## 2. 产品目标

### 2.1 核心目标

1. 支持登录凭据、SSH 密钥、信用卡、身份与地址、安全笔记五类敏感条目的完整生命周期管理。
2. 提供个人保险库和家庭共享保险库，并用明确、可验证的权限规则隔离数据。
3. 提供密码、多单词口令和 SSH 密钥生成能力。
4. 使用同一套响应式 Web UI 覆盖 PC 和移动端，并支持 Android 以 PWA 形式安装到桌面。
5. 通过 Docker 单容器运行，可选配 Cloudflare Tunnel 访问内网实例。
6. 支持多用户、整实例定时备份、成员个人导入导出、本地 7z 和 Cloudflare R2。
7. 在家庭硬件上保持较低资源占用，并且不依赖 PostgreSQL、Redis、消息队列等外部基础设施。

### 2.2 成功标准

- 新用户按照文档可以在 10 分钟内用 Docker Compose 完成首次部署和管理员初始化。
- `linux/amd64` 与 `linux/arm64` 均有可运行镜像。
- 常规家庭规模下，单实例支持至少 20 个成员、10,000 条保险库条目。
- 空闲状态内存占用以 100 MB 左右为优化目标；发布验收时记录实际值，不以牺牲正确性换取绝对上限。
- 所有敏感数据在数据库、归档和日志中均不以明文持久化。
- 权限集成测试覆盖全部角色、保险库范围和写操作组合。
- 整实例备份可以在干净环境中完成恢复演练。
- PC、手机浏览器和已安装 PWA 共享完整核心功能；PWA 不承诺离线访问保险库。

## 3. 产品原则

### 3.1 精而不杂

- 首版只实现家庭日常管理所需的条目、生成、共享、搜索、备份和恢复。
- 不在首版加入企业组织层级、审批、附件、浏览器扩展或复杂自动填充。
- 新功能必须证明其能减少数据丢失、安全风险或高频操作成本。

### 3.2 本地优先

- 应用默认面向内网部署，不要求第三方云服务才能运行。
- Cloudflare Tunnel 和 R2 均为可选能力；禁用后不影响核心保险库。
- 不将密码、密码哈希或条目内容发送到外部泄露检测、分析或遥测服务。

### 3.3 可恢复优先

- 数据结构变更、版本升级和整实例恢复都必须有明确的失败边界。
- 备份必须经过可读性和完整性验证后才算成功。
- 删除账号和整实例恢复等不可逆操作必须明确提示并二次确认。

## 4. 范围

### 4.1 V1 范围内

- 一次性系统初始化和管理员创建。
- 用户名、密码登录，会话管理和成员自助改密。
- 管理员创建、禁用、启用和删除成员。
- 个人保险库、共享保险库和固定所有权规则。
- 五类条目的创建、读取、更新、删除和恢复。
- 搜索、标签、收藏、修改历史和回收站。
- 密码、口令、Ed25519 与 RSA-4096 SSH 密钥生成。
- 个人加密导出与恢复。
- 整实例本地/R2 手动及定时备份、验证、保留与恢复。
- 安全审计、健康检查、数据库迁移和 Cloudflare Tunnel 示例。
- Newsprint 响应式 UI 和可安装 PWA。

### 4.2 V1 明确不包含

- 零知识或端到端加密。
- 离线保险库和多端离线冲突合并。
- 浏览器扩展及网页自动填充。
- 文件附件。
- TOTP 登录、Passkey、SSO 和 LDAP。
- 在条目中生成 TOTP 验证码。
- 外部密码泄露检测。
- Bitwarden、1Password、浏览器 CSV 等第三方格式迁移器。
- 企业组织、用户组、审批流和细粒度 ACL。
- 多实例部署和横向扩容。

## 5. 用户与权限模型

### 5.1 角色

系统只有两种角色：

- `admin`：拥有普通成员的保险库能力，另外可以管理账号、备份、审计和系统设置。
- `member`：管理自己的个人条目，读取共享条目，并创建共享条目。

“管理员不能读取成员个人保险库”是应用权限保证，不是密码学上的零知识保证。服务器及其运维者属于可信边界，掌握运行主机和主密钥的运维者理论上可以解密数据。

### 5.2 权限矩阵

| 操作 | 普通成员 | 管理员 |
| --- | --- | --- |
| 查看自己的个人条目 | 允许 | 允许 |
| 查看他人的个人条目 | 禁止 | 禁止 |
| 创建个人条目 | 允许 | 允许 |
| 修改/删除自己的个人条目 | 允许 | 允许 |
| 查看任意共享条目 | 允许 | 允许 |
| 创建共享条目 | 允许 | 允许 |
| 修改/删除自己创建的共享条目 | 允许 | 允许 |
| 修改/删除他人创建的共享条目 | 禁止 | 禁止 |
| 创建、禁用、删除成员 | 禁止 | 允许 |
| 查看系统管理审计 | 禁止 | 允许 |
| 配置和执行整实例备份 | 禁止 | 允许 |
| 导出/恢复自己的数据 | 允许 | 允许 |

所有授权必须在 Go 服务层执行。前端隐藏按钮只是交互优化，不能作为权限边界。

### 5.3 初始化与账号生命周期

#### 首次初始化

1. 空数据库启动时，服务生成一次性初始化令牌并写入容器日志。
2. 初始化页面要求输入该令牌、管理员用户名和管理员密码。
3. 服务使用数据库事务创建首个管理员并写入初始化完成状态。
4. 并发初始化请求只有一个能够成功。
5. 成功后初始化接口永久关闭；修改环境变量或重启服务均不能重新开放。

建议先在内网完成初始化，再启用 Cloudflare Tunnel。

#### 创建成员

- 管理员创建唯一用户名和一次性初始密码。
- 成员首次登录必须修改初始密码后才能访问保险库。
- 管理员不能读取成员当前密码。
- 成员只有在提供当前密码后才能自行修改密码。
- V1 不提供管理员重置成员密码，以免管理员通过重置后登录的方式绕过个人保险库隔离。
- 遗忘密码且没有有效登录会话时，V1 无法恢复该账号访问权；管理员只能在用户确认后删除并重建账号。

#### 禁用成员

- 立即撤销该成员的全部会话和 API 访问。
- 数据保留，重新启用后恢复访问。
- 共享条目仍保留，但禁用成员无法修改。

#### 删除成员

- 删除页明确提示管理员先通知成员导出个人备份。
- 管理员必须输入目标用户名确认。
- 删除事务撤销会话，并永久删除该成员的个人条目、历史版本、回收站内容以及由其创建的共享条目。
- 成员创建的审计事件保留，但操作者显示为已删除用户及不可逆内部 ID，不保留用户名快照。
- 删除不生成自动归档，也不能撤销。

## 6. 条目模型与功能

### 6.1 通用字段

每个条目具有以下通用概念字段：

- `id`：UUIDv7。
- `vault_scope`：`personal` 或 `shared`。
- `owner_user_id`：个人条目的所属成员。
- `created_by_user_id`：共享条目的创建者和唯一写入者。
- `item_type`：条目类型。
- `favorite`：收藏状态。
- `tags`：去重后的标签列表。
- `payload_version`：加密负载格式版本。
- `revision`：乐观锁版本号。
- `created_at`、`updated_at`、`deleted_at`。

数据库明文只保存权限判断、类型筛选、版本控制和生命周期所需的元数据。标题、用户名、网址、标签、备注和所有敏感业务字段均位于加密负载中。

### 6.2 条目类型

#### 登录凭据 `login`

- 名称
- 用户名
- 密码
- 一个或多个网址
- 备注
- 可选密码更新时间和过期提醒时间

#### SSH 密钥 `ssh_key`

- 名称
- 算法
- 公钥
- 私钥
- 可选私钥口令
- 注释
- 指纹

#### 信用卡 `credit_card`

- 卡片名称
- 持卡人
- 卡号
- 有效月份与年份
- CVV
- PIN
- 账单地址或地址条目引用
- 备注

#### 身份与地址 `identity`

- 名称
- 姓名
- 公司
- 电话
- 邮箱
- 国家/地区
- 省/州
- 城市
- 区县
- 地址行
- 邮政编码
- 备注

#### 安全笔记 `secure_note`

- 标题
- 正文

安全笔记用于恢复码、许可证等少量无法归类的数据，不引入自定义字段系统。

### 6.3 CRUD 与并发

- 列表默认按最近更新时间倒序，可按类型、收藏和标签筛选。
- 搜索先按授权范围筛选记录，再在服务进程内解密并匹配标题、用户名、网址、标签和备注。
- 更新必须携带 `revision`。版本不匹配返回冲突，不静默覆盖。
- 每次有效更新前保存一个加密历史版本，单条记录最多保留最近 10 个。
- 从历史恢复会创建新版本，不改写历史。
- 普通删除进入回收站，30 天后由后台任务永久清除。
- 共享条目只有创建者可以从回收站恢复或提前永久删除。

### 6.4 敏感字段交互

- 密码、私钥、私钥口令、卡号、CVV 和 PIN 默认遮蔽。
- 用户必须主动点击或使用键盘命令查看。
- 查看 30 秒后、页面失焦后或会话锁定后重新遮蔽。
- 复制操作写入审计日志，但不记录字段值。
- 前端在复制 30 秒后尽力清理未变化的剪贴板；浏览器不允许验证或清理时必须如实提示，不能承诺绝对清除。

### 6.5 生成器

#### 密码生成器

- 长度范围 8–128，默认 20。
- 可分别启用大小写字母、数字和符号。
- 可以排除易混淆字符。
- 至少选中一个字符类别。
- 使用操作系统加密安全随机源，不使用伪随机业务库。

#### 多单词口令生成器

- 默认 5 个单词。
- 支持 3–10 个单词、分隔符和首字母大小写选项。
- 使用随镜像发布并标明来源及许可证的固定词表。

#### SSH 密钥生成器

- 默认生成 Ed25519。
- 可选 RSA-4096，不提供更短 RSA 密钥。
- 支持可选口令和注释。
- 使用 Go `crypto/rand`。
- 私钥生成结果默认立即保存为条目；若用户取消保存，服务不得持久化或记录结果。

## 7. 搜索、标签、收藏、历史与审计

### 7.1 搜索策略

V1 面向家庭数据量，不建立敏感明文索引或复杂盲索引。服务按权限读取候选记录并在内存中解密搜索。搜索词不写入访问日志和审计日志。

验收环境中，单用户拥有 10,000 条记录时，常用关键词搜索的服务端 P95 目标为 300 ms。达不到目标时再单独设计加密索引；不得在未评审的情况下添加明文索引。

### 7.2 密码健康提示

- 在当前用户有权读取的登录凭据范围内检测弱密码、重复密码和过期密码。
- 共享条目可以参与该用户的本地结果，但不能显示其他成员的个人统计。
- 不调用第三方泄露查询服务。
- 健康结果按需计算，不把密码指纹长期存入数据库。

### 7.3 审计事件

记录以下事件：

- 初始化成功或失败。
- 登录成功、失败、退出、会话撤销和密码修改。
- 条目查看、敏感字段展示、复制、创建、更新、删除、恢复和永久删除。
- 成员创建、禁用、启用和删除。
- 个人导入导出。
- 备份配置变更、手动/定时执行、验证、清理和恢复。
- 系统迁移和关键配置变更。

审计记录包含事件类型、操作者 ID、目标类型、目标不透明 ID、结果、时间和请求关联 ID，不包含标题、用户名、网址、标签、搜索词或任何敏感值。

## 8. 系统架构

### 8.1 技术栈

- 后端：Go 当前稳定版本。
- 前端：React 19、TypeScript、Vite。
- PWA：`vite-plugin-pwa`，使用显式缓存白名单。
- 样式：Tailwind CSS，并以 `style.md` 中的 Newsprint token 为唯一视觉基线。
- 数据库：SQLite，WAL 模式。
- 数据访问：轻量 SQL 查询层和显式迁移，不引入重量级 ORM。
- 对象存储：兼容 S3 API 的 Cloudflare R2 客户端。
- 压缩：容器内固定版本的 7-Zip CLI，密码通过受控标准输入/伪终端传递，不出现在进程参数、日志或错误消息中。
- 部署：Docker、Docker Compose。

### 8.2 运行形态

```text
Browser / Installed PWA
          |
          | HTTPS
          v
Cloudflare Tunnel (optional)
          |
          | private Docker network
          v
Go application
  +-- embedded React assets
  +-- REST API
  +-- authorization services
  +-- crypto services
  +-- scheduler
  +-- backup/R2 adapter
          |
          v
SQLite + /data volume
```

应用采用模块化单体：各模块共享同一进程和数据库，但必须通过明确的服务接口协作。禁止让 HTTP handler 直接拼接权限 SQL、直接解密数据或调用 7-Zip。

### 8.3 后端模块

- `bootstrap`：初始化状态和首个管理员事务。
- `auth`：密码哈希、登录、会话、改密、限流。
- `users`：成员生命周期。
- `vault`：权限、条目、历史、回收站、搜索和健康检查。
- `generator`：密码、口令和 SSH 密钥生成。
- `transfer`：成员导入导出、格式验证和冲突策略。
- `backup`：快照、归档、验证、保留、本地/R2 和恢复。
- `scheduler`：定时任务注册、互斥和执行历史。
- `audit`：脱敏审计写入与查询。
- `settings`：非敏感系统设置。
- `platform`：SQLite、时钟、随机源、文件系统和对象存储适配器。

### 8.4 前端模块

- `app-shell`：路由、会话、全局错误和 PWA 状态。
- `design-system`：token、排版、布局原语和通用表单控件。
- `auth`：初始化、登录、首次改密和会话锁定。
- `vault`：列表、搜索、详情、编辑、历史和回收站。
- `generator`：生成器工作区。
- `transfer`：导入预览、导出和结果。
- `admin`：成员、备份、审计和系统设置。

### 8.5 API 约定

- API 前缀为 `/api/v1`。
- 使用 JSON；归档下载与上传使用流式 body。
- Cookie 会话，不把长期 token 存入 Local Storage。
- 所有写请求要求 CSRF token。
- 错误响应包含稳定的 `code`、用户安全消息和 `request_id`，不返回堆栈及底层数据库错误。
- 创建类接口支持幂等键。
- 分页使用不透明游标，不使用可猜测页偏移暴露记录量。

主要资源边界：

```text
/api/v1/setup/*
/api/v1/auth/*
/api/v1/users/*
/api/v1/items/*
/api/v1/generators/*
/api/v1/transfer/*
/api/v1/admin/backups/*
/api/v1/admin/audit/*
/api/v1/admin/settings/*
```

## 9. 数据设计

### 9.1 核心表

| 表 | 职责 |
| --- | --- |
| `system_state` | 初始化状态、模式和 schema 元信息 |
| `users` | 用户名、角色、状态和密码哈希参数 |
| `sessions` | 哈希后的会话标识、过期时间和撤销状态 |
| `login_attempts` | 限流所需的短期聚合数据 |
| `vault_items` | 条目元数据、加密负载、nonce 和 revision |
| `item_versions` | 最近 10 个加密历史版本 |
| `audit_events` | 脱敏不可变审计事件 |
| `app_settings` | 非敏感、可由 UI 调整的配置 |
| `backup_jobs` | 调度规则、目标和启停状态 |
| `backup_runs` | 每次备份的结果、大小、校验值和错误码 |

### 9.2 数据约束

- 用户名标准化后唯一，并保留原始展示形式。
- 个人条目必须有 `owner_user_id`，共享条目必须有 `created_by_user_id`。
- 数据库 CHECK 约束保证个人/共享字段组合合法。
- 外键默认启用。
- 账号删除由单个事务处理，并有覆盖全部关联表的测试。
- 审计表只追加，不提供产品层面的修改/删除接口。
- 所有时间以 UTC 存储，UI 按浏览器时区显示；备份调度显式保存 IANA 时区。

### 9.3 数据库运行参数

- 启用 WAL。
- 启用 foreign keys。
- `busy_timeout` 默认为 5 秒；超过后返回可重试的数据库繁忙错误。
- 写事务保持短小，归档和 R2 上传不能占用写事务。
- 定期执行 WAL checkpoint；不在请求高峰中执行阻塞式维护。

## 10. 安全设计

### 10.1 威胁边界

V1 防护：

- 数据库或备份文件被单独窃取。
- 普通成员越权读取或修改他人个人条目。
- 管理员通过产品 API 读取成员个人条目。
- 会话窃取、CSRF、暴力登录、注入、敏感日志和常见 Web 攻击。
- Cloudflare Tunnel 将服务暴露后产生的公网扫描和恶意请求。

V1 不防护：

- 掌握运行主机、容器内存和应用主密钥的恶意运维者。
- 已解锁浏览器、恶意浏览器扩展、系统级键盘记录器或剪贴板监控。
- 成员主动复制、截图或分享自己有权读取的共享条目。

### 10.2 密码和会话

- 登录密码使用 Argon2id。初始基线为 64 MiB 内存、3 次迭代、并行度 2；发布构建在目标架构上验证单次耗时处于 250–500 ms，并将实际参数随哈希保存。
- 密码最少 12 个字符，允许长口令和全部 Unicode；最大输入字节数必须有防 DoS 上限。
- 登录错误不区分用户名不存在和密码错误。
- 以用户名、来源地址和实例全局维度联合限流。
- 会话 ID 至少 256 bit 随机，只在数据库保存其哈希。
- Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax` 和限定路径。
- 默认闲置 15 分钟锁定，可由用户在安全范围内调整；绝对会话期限为 24 小时。
- 改密、禁用、删除账号和管理员主动撤销都会使已有会话失效。

### 10.3 条目加密

- 使用 XChaCha20-Poly1305 字段负载加密。
- 每个负载使用独立随机 24-byte nonce。
- 附加认证数据至少绑定条目 ID、保险库范围、属主/创建者 ID、负载格式版本和 revision。
- 主密钥为 256 bit，通过只读 Docker Secret 文件挂载；不写入数据库、镜像或普通配置导出。
- 解密只发生在完成授权之后。
- 敏感明文不得进入结构化日志、错误包装、指标 label 或审计数据。
- 加密格式带版本号，为未来密钥轮换和算法迁移保留空间。

### 10.4 HTTP 和代理安全

- 生产环境只信任显式配置的代理网段和 Cloudflare 入口，不无条件信任 `X-Forwarded-*`。
- 设置 CSP、HSTS、`X-Content-Type-Options`、`Referrer-Policy` 和 frame 限制。
- 前后端同源，CORS 默认关闭。
- 初始化、登录、导入和归档接口使用更严格的大小、频率和超时限制。
- 上传归档先验证大小、7z 结构、文件白名单、展开后总大小和路径，防止压缩炸弹及目录穿越。

## 11. 备份与恢复

### 11.1 整实例备份内容

加密 7z 包包含：

- 通过 SQLite Online Backup API 生成的一致性数据库快照。
- 应用主密钥。
- `manifest.json`。
- 恢复所需且允许持久化的非敏感配置快照。

不包含 R2 access key、R2 secret key、Cloudflare token、备份口令、TLS 私钥和运行日志。

`manifest.json` 至少包含：

- 备份格式版本。
- 应用版本和数据库 schema 版本。
- 备份 ID、创建时间和实例 ID。
- 各文件的大小与 SHA-256。
- 原始架构信息。

### 11.2 备份目标

- 本地：写入 `/data/backups` 或显式配置的挂载目录。
- R2：上传到配置的 bucket/prefix，使用临时对象名；验证完成后再提交最终对象名。
- 两个目标独立执行和报告，一个失败不能把另一个已成功的结果标记为失败。

### 11.3 备份执行

1. 获取备份互斥锁，防止定时与手动任务重叠。
2. 检查临时空间和目标配置。
3. 创建 SQLite 一致性快照。
4. 生成清单和校验值。
5. 使用独立备份口令和 7z AES-256 加密；启用文件名加密。
6. 用受限资源重新打开归档，验证清单与校验值。
7. 原子移动到本地最终路径和/或上传 R2。
8. 写入执行记录。
9. 仅在新备份验证成功后应用保留策略。
10. 清理临时文件。

备份口令通过 Docker Secret 文件提供。7-Zip 密码不得出现在命令行参数、日志或进程错误中。

### 11.4 调度与保留

- 支持管理员手动立即执行。
- 支持可配置的每日执行时间和 IANA 时区。
- 默认祖父-父-子保留策略：7 个日备份、4 个周备份、6 个月备份。
- 本地与 R2 可分别启停和调整保留数量。
- 清理操作逐个目标执行；删除 R2 对象失败时保留记录并在下次重试。

### 11.5 整实例恢复

整实例恢复不在正常 Web 请求中覆盖运行数据库。提供容器命令：

```bash
tiny-password restore /restore/backup.7z
```

恢复流程：

1. 确认应用未处于正常服务模式。
2. 读取备份口令 Secret。
3. 验证归档格式、应用兼容范围、全部校验值和磁盘空间。
4. 为当前实例创建恢复前快照。
5. 解压到同文件系统的临时目录。
6. 使用归档内的源主密钥解密敏感负载，再使用目标实例已挂载的新主密钥重新加密；源主密钥只存在于受限临时目录和进程内存中。
7. 原子替换数据库，清理归档中的源主密钥及其他临时文件。
8. 运行数据库迁移和完整性检查。
9. 成功后允许正常启动；失败则保留原实例和错误报告。

### 11.6 成员个人导入导出

- 导出只包含成员个人条目和由该成员创建的共享条目。
- 导出时成员单独输入并确认归档密码；该密码不要求等于登录密码，也不被保存。
- 服务端流式生成加密 7z，下载结束或请求中断后清理临时文件。
- 归档包含版本化 JSON 清单、条目数据和校验值，不包含用户密码哈希、会话或审计日志。
- 导入先解密、校验和展示类型/数量摘要，用户确认后才写入。
- 类型无效、字段超限或归档损坏时整体拒绝，不部分写入。
- ID 与现有条目冲突时生成新 ID 并作为新条目导入，不覆盖现有数据。
- 导入的个人条目属于当前用户；导入的共享条目由当前用户创建。

## 12. UI/UX 设计

### 12.1 视觉基线

UI 必须遵循仓库根目录 `style.md` 的 Newsprint 设计系统：

- 永久浅色模式。
- 背景 `#F9F9F7`、前景和主边框 `#111111`、弱分隔 `#E5E5E0`、强调 `#CC0000`。
- 全部元素零圆角，无渐变、模糊或柔和阴影。
- 使用明确的横纵网格边框和共享边框，形成报纸栏目结构。
- Playfair Display 用于标题，Lora 用于说明正文，Inter 用于 UI，JetBrains Mono 用于密码、日期和技术数据。
- 动效快速、机械、克制，并尊重 `prefers-reduced-motion`。

密码管理工作区以清晰和操作效率为先：不在日常保险库页面滥用 9xl 标题、跑马灯、装饰性 drop cap 或大面积倒置区块。Newsprint 的个性主要由字体、网格、边框、密度和黑白反转交互表达。

### 12.2 信息架构

公共页面：

- 首次初始化
- 登录

成员页面：

- 个人保险库
- 共享保险库
- 收藏
- 生成器
- 回收站
- 个人导入导出
- 账户与会话设置
- 个人活动记录

管理员页面：

- 成员管理
- 整实例备份
- 系统审计
- 系统设置与运行状态

### 12.3 桌面布局

- 顶部报头展示产品名、当前保险库、当前成员和锁定/退出入口。
- 主区域使用 12 栏：左侧紧凑导航，中间条目列表，右侧详情或编辑工作区。
- 条目列表使用带共享边框的行，不使用圆角卡片墙。
- 宽度不足时详情切换为独立页面，避免内容被挤压。
- 个人/共享范围必须通过页面标题、栏目标签和所有者署名共同表达，不能只依赖颜色。

### 12.4 移动布局

- 小于 768px 时切换为单栏。
- 使用带上边框的底部主导航切换保险库、共享、生成器和设置。
- 查看、编辑和历史使用全屏页面。
- 表格转为带分隔线的字段列表，不允许水平滚动承载主要操作。
- 所有触控目标至少 44×44 px。

### 12.5 关键状态

必须设计并测试：

- 首次初始化与初始化令牌错误。
- 空保险库和无搜索结果。
- 会话即将过期、已锁定和已撤销。
- 共享条目只读状态及创建者身份。
- revision 冲突和重新加载选择。
- 导入预览、部分目标不可用和完整失败。
- 备份运行中、成功、失败和最近从未成功。
- R2 未配置、本地空间不足和系统处于维护状态。

### 12.6 可访问性

- 使用语义化页面结构和正确标题层级。
- 所有输入都有持久可见标签；不得只使用 placeholder。
- 图标按钮有可访问名称。
- 键盘可以完成所有功能，焦点顺序与视觉顺序一致。
- `#111111` 与 `#F9F9F7` 保持高对比；颜色不是唯一状态信号。
- 错误摘要可被屏幕阅读器立即感知并链接到具体字段。

## 13. PWA 与前端数据安全

- Web App Manifest 提供名称、图标、主题色、显示模式和启动 URL。
- Service Worker 只预缓存带内容哈希的静态应用资源和离线说明页。
- `/api/`、归档下载、用户头像之外的任何动态响应均不得进入 Cache Storage。
- V1 不将解密后的保险库写入 IndexedDB、Local Storage 或 Service Worker。
- 页面刷新或浏览器重启后必须重新从服务端取得授权数据。
- 应用更新时提示用户刷新，不在未保存表单中强制刷新。

## 14. Docker 与 Cloudflare 部署

### 14.1 主应用容器

- 多阶段构建：Node 阶段构建 React，Go 阶段编译并嵌入静态资源，最终使用精简非 root 镜像。
- 暴露单一 HTTP 端口供容器网络访问。
- `/data` 为唯一必需持久卷。
- 应用主密钥和备份口令以只读 Secret 文件挂载。
- 支持优雅停机，停止接收新请求并等待短事务完成。

### 14.2 Compose 交付

基础 Compose 只包含主应用。可选 `tunnel` profile 增加 `cloudflared`：

- Tunnel token 通过 Secret/环境注入，不写入仓库。
- `cloudflared` 通过 Docker 服务名访问主应用。
- 主应用不需要映射到宿主公网地址。
- 文档同时给出仅局域网端口映射的配置。

### 14.3 健康与可观测性

- `/healthz`：进程存活，不访问敏感依赖。
- `/readyz`：数据库可用、迁移完成、主密钥有效。
- 日志使用结构化 JSON，可切换人类可读格式。
- 指标仅包含请求量、延迟、错误码、任务结果和数据库状态，不包含用户名、条目 ID 或路径参数。
- V1 不内置遥测上报。

## 15. 错误处理与一致性

- 所有多表写入使用事务。
- 创建接口通过幂等键避免网络重试产生重复条目。
- 更新冲突返回专用错误码和当前 revision，不自动合并敏感字段。
- 备份、导入、生成任务使用明确的资源上限和超时。
- 临时敏感文件权限限制为当前容器用户，任务结束后无论成功失败都清理。
- R2 上传采用可重试错误分类；认证失败等永久错误不无限重试。
- 后台任务崩溃不能导致主 HTTP 服务崩溃，但必须记录失败并在管理页突出显示。
- 数据库迁移在事务或可恢复步骤中执行；升级前创建快照，失败时拒绝进入 ready 状态。

## 19. 后续候选功能
